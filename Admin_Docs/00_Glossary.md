## 개발자 상세

| 용어 | 쉬운 말 |
|---|---|
| 프론트(프론트엔드) | 브라우저에 보이는 화면을 그리는 코드 |
| 백엔드(서버) | 화면 뒤에서 데이터를 찾아 주고 계산하는 프로그램 |
| API | 화면이 서버에 "이거 줘" 하고 보내는 요청의 약속된 형식. 식당 주문서 같은 것 |
| 해시 라우팅 | 주소의 `#` 뒷부분(`#/flaseek/list`)으로 화면을 바꾸는 방식. 서버는 한 페이지만 주고 브라우저가 알아서 화면을 갈아 끼워요 |
| lazy(지연 로딩) | 그 화면에 들어갈 때 코드를 받는 것. 처음 열 때 필요한 것만 받아서 빨라요 |
| 컴포넌트 | 화면을 이루는 레고 블록. 버튼, 상품 카드 같은 조각 |
| 상태(state) | 화면이 기억하고 있는 값. 장바구니 수, 찜 목록처럼 바뀌면 화면이 다시 그려져요 |
| 디자인 토큰 | 색·글자 크기·간격에 붙인 이름. `flaseek` = 버튼 핑크처럼 이름으로 부르면 값이 한곳에서 바뀌어요 |
| 반응형 | 같은 화면이 PC(넓은 화면)와 모바일(좁은 화면)에서 각각 맞게 배치되는 것 |
| 시안 | 실제 서비스가 아닌 "이렇게 바꾸면 어떨까" 하고 보여 주는 제안 화면 |
| mock(목) | 진짜 대신 쓰는 가짜 데이터·가짜 서버. 키가 없거나 실제 사장님께 알림이 가면 안 될 때 써요 |
| 정적 빌드 | 서버 없이 파일만으로 열리는 완성본 |
| 대비(명도 대비) | 글자와 배경의 밝기 차이. 4.5 : 1 이상이어야 잘 읽힌다는 접근성 기준(WCAG)이 있어요 |
| 접근성 | 키보드만 쓰는 사람, 화면 낭독기를 쓰는 사람도 쓸 수 있게 만드는 것 |
| 테스트셋(시험지) | 검색어와 "이게 나와야 한다"는 정답을 묶어 둔 목록. 검색을 고칠 때마다 같은 시험지로 채점해요 |
| 베이스라인 | 고치기 전에 처음 잰 점수. 다이어트 전 몸무게처럼, 나중 점수와 비교하는 기준이에요 |
| 0건 비율 | 결과가 하나도 안 나온 검색어의 비율. 낮을수록 좋아요 |
| 상위 3 적중률 | 정답이 결과 1~3위 안에 든 검색어의 비율. 높을수록 좋아요 |
| MRR | 첫 정답이 몇 위에 나왔는지를 점수로 바꾼 평균. 1위면 1점, 2위면 0.5점, 못 찾으면 0점이에요 |
