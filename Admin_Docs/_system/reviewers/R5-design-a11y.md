# R5 디자인·접근성 (화면이 바뀐 기능만)

담당 모델: Sonnet

> 고정 체크리스트. 내용을 바꾸지 않는다. 리뷰 결과는 `features/F-00X-제목/review/R5.md`에 쓴다. 리뷰 패킷을 기준으로 보고, 패킷으로 판단이 안 되는 항목만 해당 파일을 연다.

- 기준 자료: overview/design-link.md가 가리키는 원본(피그마, 디자인 md·토큰 파일)을 직접 열어 비교한다. 바뀐 화면에 해당하는 부분만 연다.
- 토큰을 쓰는가(색·간격·폰트 값을 직접 박지 않았나)
- design-link.md 매칭 표의 컴포넌트를 재사용하는가, 상태(기본/호버/비활성/에러)를 다 구현했나
- overview/screens.md의 흐름과 화면 이동이 맞는가, 반응형(PC·MO)
- 접근성: 키보드 사용, 대체 텍스트, 폼 라벨, 색 대비(아래 세 묶음으로 판정)
- 색 대비 — 세 묶음 (WCAG 2.2 AA). 디자인 md에 대비 판정 표(① · ② · ③)가 있으면 그것이 기준이다. 대비 값은 실제 CSS 값(토큰을 풀어낸 hex, opacity 합성 후)으로 계산하고, 계산 못 하면 "미확인"
  - ① 반드시 맞춤 — 미달이면 [위험]: 본문 글자 4.5:1, 큰 글자(24px 이상 또는 19px 이상 bold) 3:1, 정보를 전달하는 UI 3:1(의미 있는 아이콘, 필드의 유일한 단서인 입력 테두리, 체크박스·라디오·토글 경계와 선택 표시, 포커스 링). 호버·선택·오류 상태와 다크 모드도 각각 본다. 이미지·그라데이션 위 글자는 오버레이가 있는지 본다
  - ① 색만으로 의미 전달 — [주의]: 오류·선택·필수 표시가 색뿐인지, 본문 속 링크가 색으로만 구분되는지(밑줄 또는 주변 글자와 3:1)
  - ② 일부러 낮춘 것 — 지적하지 않는다: 비활성(disabled, WCAG 예외), 라벨이 따로 있는 플레이스홀더, 정보 없는 장식 테두리·구분선·배경, 로고. 결과 줄에 "② 의도 — 근거: {디자인 md 위치 또는 예외 조항}"으로 쓰고 끝낸다. 플레이스홀더가 유일한 안내면 ②가 아니라 ①
  - ② 근거가 디자인 md에 없으면 [주의]로 "의도인지 확인 필요"만 남긴다([위험] 아님)
  - ③ 디자인 md가 "쓰지 않는다"고 막은 조합을 코드에서 썼으면 [위험]
