## 지적 (있을 때)
- [주의] "포인트가 부족한가"를 세 군데에서 따로 판단하고, 그중 모달 쪽 판단은 화면에서 닿지 않아요. `useEnroll`이 `remaining < 0`이면 버튼을 `short`로 만들고, `open()`은 `available`일 때만 모달을 열어요. 그래서 `EnrollModal`의 포인트 부족 상태(빨간 잔여 · 경고 · 신청하기 비활성)와 `api.ts`의 400은 정상 흐름에서 나오지 않아요. feature.md는 "포인트 부족은 모달이 먼저 막고"라고 적었지만, 실제로는 버튼이 먼저 막아요. — 위치: `projects/techlearn/hooks.ts` `useEnroll`(`state` 계산, `open`), `enroll.tsx` `EnrollModal`(`short`), `api.ts` `enrollCourse`, `F-008 feature.md` 결과 "수강신청" 줄 — 고치는 방법: 어느 쪽이 의도인지 사용자에게 먼저 물어요. (a) 버튼이 막는 게 맞으면 문서를 "버튼이 먼저 막고, 모달의 부족 상태는 시안 재현용"으로 고치고 모달의 `short` 분기는 남길지 정해요. (b) 시안 03-3처럼 모달에서 보여 주려면 `open()`이 `short`에서도 모달을 열게 바꿔요. 어느 쪽이든 부족 판단은 `lectures.ts`나 `store.ts`에 함수 하나(예: `remainingAfter(points, price)`)로 두고 세 곳이 같이 써요.
- [제안] 숫자 표시 함수가 두 데이터 파일에 흩어져 있어요. `won`·`rating`은 홈용 `data.ts`에, `points`는 `lectures.ts`에 있어요. 그래서 강의 목록·상세 화면이 홈 홍보 데이터 파일(`data.ts`)을 `rating` 하나 때문에 불러와요. — 위치: `screens/CourseListScreen.tsx` 5줄, `screens/CourseDetailScreen.tsx` 12줄 `import { rating } from '../data'` — 고치는 방법: `format.ts`를 만들어 `won`·`points`·`rating`을 옮기고, `data.ts`·`lectures.ts`는 데이터만 갖게 해요.
- [제안] `routes.ts` 주석의 예시가 실제 주소 규칙과 달라요. 주석은 `techlearnHref('/courses', { cat: 'ai' })`인데, 강의 목록은 `tab`과 `q`만 읽고 `cat`은 아무 데서도 읽지 않아요. — 위치: `projects/techlearn/routes.ts` `techlearnHref` 주석 — 고치는 방법: 예시를 `{ tab: 'backend' }`처럼 실제로 쓰는 파라미터로 바꿔요.
- [제안] 홈 '최근 기록'의 출처 칸이 화면용 문장을 잘라서 만들어요. `item.design?.app.split(' — ')[0]`은 `app` 문장에 " — "가 있다는 약속에 기대요. 지금 Design 사례 8개는 모두 지켜요. 하지만 문장을 고치다가 구분자가 바뀌면 출처가 문장 전체로 나와요. — 위치: `portfolio/SearchHome.tsx` `RECENT`의 `source` — 고치는 방법: `DesignCase`에 `appName` 같은 짧은 이름 칸을 두거나, 지금 방식을 유지할 거면 `data.ts`의 `app` 타입 주석에 "'이름 — 설명' 형식"을 적어 둬요.
- [제안] 구조 문서가 이번 변경을 다 따라오지 못했어요. ① [data-model.md](../../../overview/data-model.md) "1) 프론트 정적 데이터" 표에 techlearn `Lecture`(lectures.ts) · `Course`(data.ts)와 포트폴리오 `PROJECTS`가 없고, "2) 화면 상태"에 techlearn `store.ts`(포인트 · 수강 기록)가 없어요. ② [architecture.md](../../../overview/architecture.md) "프론트 라우팅"은 아직 "프로젝트 앱 3개는 lazy"라고 적혀 있는데, 지금은 4개(Accio · 마에스트로 · FLASEEK · techlearn)예요. ③ [screens.md](../../../overview/screens.md)의 "techlearn 흐름" 칸이 문서 끝 "최종 수정" 줄 아래에 붙어 있어요. — 고치는 방법: ①은 표에 두 줄, 화면 상태에 한 줄을 더해요. ②는 "4개"로 고쳐요. ③은 "FLASEEK 화면" 칸 다음으로 옮기고 "최종 수정" 줄을 맨 끝에 둬요.

## 체크 항목별 근거 (항상 작성)
- 프론트 · 컴포넌트 책임 (techlearn) → `TechlearnApp.tsx`는 `path`로 화면만 골라요(`/courses`, `/course/{id}`, 나머지는 홈). `screens/` 3개는 화면 하나씩, `components.tsx`는 여러 화면이 같이 쓰는 조각(Logo · Header · Footer · SectionTitle · CourseCard · Breadcrumb), `enroll.tsx`는 모달 · 토스트 그리기만, `hooks.ts`는 검색 이동(`useCourseSearch`)과 수강신청 상태(`useEnroll`), `api.ts`는 서버 판단 흉내, `store.ts`는 상태 보관만 해요. `CourseDetailScreen`은 `findLecture` → 없으면 `NotFound`, 있으면 `key={lecture.id}`로 `CourseDetail`을 새로 시작해서 강의가 바뀔 때 모달 · 토스트가 남지 않아요. 상세 카드(`EnrollCard`)와 모바일 하단 바(`MobileEnrollBar`)는 `useEnroll` 결과 하나를 함께 받아서 버튼 상태가 둘로 갈라지지 않아요. 책임 분리는 문제 없어요. 판단 중복은 지적 1.
- 프론트 · 의존 방향 (techlearn) → screens → hooks → api → store, lectures 순서로 한쪽으로만 흘러요. `enroll.tsx`는 `hooks.ts`에서 `Toast` 타입만 가져오고, `hooks.ts`는 `enroll.tsx`를 부르지 않아서 순환이 없어요. `projects/techlearn/` 안에서 `../../`, `shared/`, `portfolio/`를 부르는 곳이 없고, 거꾸로 `portfolio/`·`shared/`도 techlearn을 부르지 않아요(grep으로 확인). 홈 화면 파일 하나가 `data.ts`를 쓰는 건 맞지만, 강의 화면이 `rating` 때문에 `data.ts`를 부르는 건 지적 2.
- 프론트 · 폴더 구조와 architecture.md 일치 → architecture.md 폴더 트리의 `techlearn/ (TechlearnApp, routes, data(홈), lectures(강의 8개), store, api, hooks, components, enroll, screens/)`와 실제 파일 목록이 같아요. 이미지 · 아이콘은 `assets/`에 모여 있어요(트리에는 없지만 flaseek도 같은 방식). 다른 프로젝트처럼 `routes.ts`에 `TECHLEARN_BASE`와 `techlearnHref()`를 두는 패턴도 지켰어요. "프로젝트 앱 3개" 문구만 남았어요(지적 5).
- 프론트 · 라우팅과 D-001 → `App.tsx`에 `lazy(() => import("./projects/techlearn/TechlearnApp"))` 한 줄과 `subPath(path, TECHLEARN_BASE)` 라우트 하나를 더했어요. `subPath`는 `base` 자체이거나 `base/`로 시작할 때만 맞아서 `/techlearnx` 같은 주소는 잡지 않아요. 포트폴리오 쪽 라우트(`/search`, `/case/`, `/study/`)보다 먼저 검사해도 겹치는 주소가 없어요. `App.tsx`는 `TECHLEARN_BASE`만 바로 불러오고 화면 코드는 lazy라서, 포트폴리오 첫 화면은 techlearn 화면 코드를 받지 않아요. 해시가 바뀔 때 `scrollTo(0, 0)`은 `App.tsx`의 기존 `useEffect`가 그대로 맡아요.
