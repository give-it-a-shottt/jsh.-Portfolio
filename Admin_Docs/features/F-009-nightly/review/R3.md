## 발견 목록

1. [주의] `hooks.ts:20` 모르는 질문 처리가 `COACH_ANSWERS[question] ?? COACH_FALLBACK` 인데 `COACH_ANSWERS`는 일반 객체라 `constructor`, `toString`, `__proto__` 같은 질문(주소 `?q=constructor` 포함)이 들어오면 함수가 돌아와 `??`를 통과하고, `CoachScreen.tsx:92`의 `message.text.slice`에서 화면이 통째로 깨진다. 고치는 방법: `Object.hasOwn(COACH_ANSWERS, question) ? COACH_ANSWERS[question] : COACH_FALLBACK` 로 바꾸거나 `COACH_ANSWERS`를 `Map`으로 둔다. 이 입력은 자동 테스트 1순위.
2. [제안] `App.tsx:68-74` `NightlyApp` 라우트에 오류 경계가 없어 위 같은 렌더 오류가 나면 포트폴리오 전체가 빈 화면이 된다. 고치는 방법: 프로젝트 라우트 공통 Error Boundary를 한 번 두거나(다른 프로젝트에도 이득), 최소한 발견 1을 막는다.
3. [제안] `NightlyApp.tsx:16` 모르는 경로(`#/nightly/xxx`, `/sleep/` 끝 슬래시 포함)가 홈 화면을 그리지만 주소창은 그대로라 사용자가 잘못 입력한 줄 모른다. 고치는 방법: 모르는 경로면 `location.replace(nightlyHref())` 로 홈으로 보내거나 "없는 페이지" 문구를 한 줄 둔다. 지금은 시안 단계라 우선순위 낮음.
4. [제안] `data.ts:17-22` vs `data.ts:36-55` 단계 카드(깊은 잠 112분·REM 98분·깨어남 20분)와 그래프 막대 합(깊은 잠 130분·REM 106분·깨어남 15분)이 서로 다르다. 가짜 데이터라 동작 문제는 아니지만 "숫자가 안 맞는다"는 지적을 받을 수 있다. 고치는 방법: 그래프 막대에서 단계별 합을 계산해 카드 값을 만들거나, 막대를 카드 값에 맞춘다(시안 모양이 우선이면 이 항목은 의도로 기록).
5. [제안] `hooks.ts:35`, `NightlyApp.tsx:15` 요청 제한 횟수(used)가 `CoachScreen`의 상태라 다른 화면에 갔다 오거나 `?q=`를 바꾸면 3/5로 되돌아간다. 실제 Redis 제한(서버 기준)과 다른 동작이다. 시안이라 괜찮지만, 문서(결과 칸)에 "제한은 화면을 나가면 초기화되는 흉내"라고 적어 두면 면접 때 설명하기 쉽다.
6. [제안] `hooks.ts:63-75` 한 이벤트 안에서 `ask`가 연달아 두 번 불리면 `streaming` 값이 옛 렌더 기준이라 둘 다 통과할 수 있다. 버튼 클릭은 렌더 사이에 끼므로 실제로는 거의 안 생기지만, 훅 자체 방어를 원하면 `useRef`로 "보내는 중" 표시를 같이 둔다.
7. [제안] 테스트: 자동 테스트가 없다. 도입(vitest)은 R2 리뷰가 필요한 패키지 추가라 이번에는 미뤄도 되지만, 도입하면 이 순서로 시작한다. (1) `useCoachChat`: 빈·공백·101자 질문, 모르는 질문(`constructor` 포함), 스트리밍 중 재질문 거부, 5/5 도달 후 거부, 가짜 타이머로 60초 뒤 `used`가 0으로 돌아오는지, 언마운트 시 타이머 정리. (2) `nightlyHref` 인코딩(한글·공백·`&`). (3) `percentOfNight`와 `duration` 같은 순수 함수. 화면 스냅샷은 마지막. 그때까지는 위 (1)의 "1분 뒤 해제"를 Playwright로 한 번 기다려 확인해 두면 좋다.
