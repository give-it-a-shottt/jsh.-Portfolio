## 발견

1. [제안] `Admin_Docs/overview/architecture.md` — Nightly가 구조 그림과 폴더 목록에 없다(techlearn은 17·38줄에 있음). 구조 문서와 코드가 어긋난 상태다. 고치는 방법: 프로젝트 줄에 `NightlyApp ─ lazy (가짜 데이터만, 화면 3개)`와 폴더 한 줄을 더한다. 문서 작업이라 사용자 승인 후에 적는다.
2. [주의] `screens/CoachScreen.tsx:27-32` — CONTEXT_ROWS의 깊은 잠 26%·REM 23%·총 수면 7h 12m이 `data.ts`의 LAST_NIGHT와 같은 값을 손으로 다시 적은 것이다(`hooks.ts:15` GREETING의 87점, SleepScreen SUMMARY의 7h 12m도 같음). 한쪽만 바꾸면 화면끼리 숫자가 달라진다. 고치는 방법: 퍼센트는 `LAST_NIGHT`/`STAGES`에서 꺼내 만들고, 총 수면·점수는 `data.ts`에 상수(`TOTAL_SLEEP`)로 두어 GREETING·SUMMARY·CONTEXT_ROWS가 함께 쓰게 한다.
3. [제안] `screens/SleepScreen.tsx:167` — 범례 단계 순서 `['deep','rem','light','awake']`를 직접 적었다. `data.ts`의 STAGES 키 순서와 같은 정보다. 고치는 방법: `data.ts`에 `STAGE_ORDER`를 두거나 `Object.keys(STAGES)`를 쓴다.
4. [제안] `screens/CoachScreen.tsx:117` — `CoachScreen` 본문이 PC용과 모바일용 JSX를 한 함수에 담아 길고, 곳곳이 `pc ? … : …` 삼항이다(ProductCard, Message, Typing). 지금은 읽을 만하지만 화면이 늘면 불어난다. 또 `AiAvatar`의 `size: Size | 'head'`에서 'head'는 사실상 "PC 크기"라 값이 겹쳐 헷갈린다(34, 267, 293줄). 고치는 방법: 크기 차이를 `SIZE_STYLE = { pc: {...}, mobile: {...} }` 객체 한 곳으로 모으고, 'head'는 'pc'로 쓰거나 이름을 분리한다. 입력창(폼)은 `Composer` 같은 컴포넌트로 뺀다.
5. [제안] `hooks.ts:21`, `screens/HomeScreen.tsx:67` — `60_000`(요청 제한 해제까지 1분)과 `240`(막대 꽉 찬 길이 4시간)은 이름이 없다. `RATE_LIMIT`은 `data.ts`에 있는데 같은 제한의 시간 창은 훅 안에 숨어 있다. 고치는 방법: `RATE_WINDOW_MS`를 `RATE_LIMIT` 옆에 두고, 240은 `FULL_BAR_MINUTES` 상수로 뺀다.
6. [제안] `assets/` — 같은 그림이 접두어만 달리 여러 번 있는 듯하다(h-watch / m-watch, c-sparkles-white / s-sparkles-white, s-chev / c-chev, s-left / mc-left 등). 피그마에서 그대로 내려받은 결과라 이해는 되나 52개 중 일부는 중복이다. 고치는 방법: 내용이 같은 파일은 하나만 남기고 import를 맞춘다(바이트 비교는 하지 않았음).
7. [제안] `components.tsx:30`, `components.tsx:246` — `Mark`의 `size`·`rounded`와 `TabBar`의 `active`가 모두 자유 문자열이다. TabBar는 탭 이름(라벨 "수면")과 문자열이 같아야 켜져서, 라벨을 바꾸면 조용히 꺼진다. 고치는 방법: TabBar의 `active`를 `'home'|'sleep'|'coach'` 같은 키로 받고 TABS에 key를 둔다(Header의 NavKey와 같은 방식).
