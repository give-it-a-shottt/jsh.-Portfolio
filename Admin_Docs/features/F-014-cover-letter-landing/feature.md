## 결과 (AI 작성 — 구현 후)
- 첫 방문 판단(탭마다 한 번): `PortfolioApp.tsx`가 처음 그릴 때 주소가 `#/`이고 sessionStorage `jsh-landing-seen`이 없으면 홈 대신 랜딩을 그려요(`landing/landingSeen.ts`). 랜딩이 화면에 뜬 순간 '봤음'을 기록해요. 건너뛰기 · '포트폴리오 보러 가기'는 홈 맨 위로. 랜딩이 떠 있다가 다른 주소로 나가면(링크 · 주소창) 이전 주소와 비교해 다시 띄우지 않아요. 다른 주소로 먼저 들어오면 그 탭에서는 띄우지 않아요 — `App.tsx`가 탭의 첫 주소를 기억해 홈이 아니면 '봤음'으로 기록해서, 마에스트로 같은 다른 앱 화면을 거쳐 홈에 와도 안 떠요(Q-008).
- 실패 대비: 랜딩만 감싸는 오류 경계(`landing/LandingBoundary.tsx`) — 랜딩 조각을 못 받거나 그리다 실패하면 빈 화면 대신 홈을 보여 줘요(이때는 '봤음'을 기록하지 않아서 새로고침하면 다시 시도해요).
- 랜딩(`landing/CoverLanding.tsx`): 첫 화면 → 01 군대 · 02 정글 · 03 지금 → 성공 기준 문장 → 04 디딤 · 05 디자인 → 06 마무리. 글은 `landingContent.ts`에 원문 그대로 모았어요.
- 움직임: 모두 스크롤 위치에 묶여요(`landing/useScrollProgress.ts`). 문장은 화면 아래에서 올라오며 진해지고, 오른쪽 그림(`LandingStages.tsx`)은 무대가 2/3쯤 보일 때 시작해 지나갈 때 끝나요. PC는 왼쪽 진행선, 모바일은 위 진행 막대. 움직임 줄이기 설정이면 진행값을 늘 1로 줘서 다 펼쳐진 상태로 보여요.
- 번들: 랜딩은 첫 방문 때만 받도록 나눴어요(`lazy`). 메인 943KB 그대로, 랜딩 조각 29.8KB(gzip 10.9KB).
- 자동 검사(`npm run check`): 첫 방문 판단(처음 · 기록 후 · 저장소 막힘 · 저장소 없음), 오류 경계(평소 렌더 · 실패 상태 · 실패 시 null · 홈으로 넘기기 1회), 글 데이터(장 id · 문장 · 내부 링크 · 강조 단어 · 뺀 문단 단어가 없는지), 첫 주소 기록(Q-008) 20개.
