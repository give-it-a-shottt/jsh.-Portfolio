## 지적 (있을 때)
- [주의] ⚠️ 로그인 없는 공개 엔드포인트 `POST /api/picks/places/{place_id}/seat-ask`의 입력에 범위가 없고, 요청마다 쌓이는 메모리를 지우지 않는다 — `SeatAsk.people`은 그냥 `int`(1~10은 프론트만), `place_id` 길이 제한 없음, `MockYumiClient._queries` · `_fixed_answers`가 계속 늘고 `ask_live_status`는 매번 전체를 돈다 — `app/picks/schemas.py SeatAsk`, `app/picks/router.py ask_seat`, `app/yumi/mock.py simulate_seat_ask · ask_live_status` — `people: int = Field(2, ge=1, le=10)`, `place_id`에 `Path(max_length=64, pattern=...)`, 가능하면 있는 id인지 확인, 오래된 질의(예: 10분)를 지우거나 최대 개수를 둔다.
- [주의] 💡 real 모드에서 유미 실패를 캐시하지 않아 장애 · 한도 소진 중에도 요청마다 유미를 다시 부르고 최대 약 40초(20초 × 재시도 1회)를 기다린 뒤 저장본이 나간다. 캐시가 빈 동네의 동시 요청은 같은 검색을 여러 번 보낸다. Render 무료 서버가 잠들면 메모리 캐시도 사라진다 — `app/picks/service.py load_places`, `app/yumi/real.py _send · _get` — 실패하면 그 동네를 일정 시간(10~30분, 429면 자정까지) "저장본 사용"으로 캐시, 동네마다 `asyncio.Lock`, picks 경로는 타임아웃을 짧게(예: 8초) 하고 재시도는 뺀다.
- [제안] 저장본으로 넘어가는 조건이 `YumiError`뿐이라 빠지는 경우가 있다 — ① `YUMI_API_KEY`가 비면 의존성 단계에서 401이 나 `/api/picks`가 모두 502, ② 예상과 다른 본문이면 `response.json()["data"]`의 JSON 오류 · KeyError가 500 — `app/yumi/deps.py _real_client`, `app/yumi/real.py _get`, `app/picks/service.py load_places` — 파싱 오류도 YumiError로, 키가 비면 저장본 경로로(또는 시작 시 경고).
- [제안] 지도 핀 HTML 문자열에 외부 데이터(`initial`)를 이스케이프 없이 넣는다. 지금은 한 글자라 공격으로 이어지지 않지만 필드를 늘리면 XSS — `MapView.tsx pinIcon` — `createElement` + `textContent`로 만든 요소를 `L.divIcon({ html: element })`에 넘기거나 이스케이프.
- [제안] `npm audit` high 2건(vite 8.3.0~8.3.2, source-map-js 1.0.0~1.2.1) — 이번 변경과 무관한 빌드 · 개발 도구 — 별도 작업으로 `npm audit fix` 후 build 확인.
