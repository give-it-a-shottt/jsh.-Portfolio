## 지적 (있을 때)
- [주의] 같은 목록을 프론트와 백엔드가 각자 하드코딩한다 — 동네 4곳(`routes.ts DONGS` · `service.py DONGS`), 상황 칩 6개(`routes.ts CONDITIONS` · `conditions.py CONDITIONS`), 시연 시각(`routes.ts DEMO_TIMES` '1240' · `service.py DEMO_TIMES` '12:40'). `ResultScreen` 상단 칩은 프론트 라벨, 카드의 맞은 조건은 서버 라벨이라 한쪽만 고치면 어긋난다 — 프론트 목록에 "서버와 키·라벨이 같아야 한다" 주석, 또는 칩 라벨을 서버 응답으로 덮어쓰기, 또는 일치 확인 테스트.
- [주의] `SeatSheet`의 첫 `useEffect`가 `[onClose]`에 의존하는데 `PlaceDetailBody`가 렌더마다 새 함수를 넘겨, 다시 렌더될 때 `opener?.focus()` → `panel.focus()`로 초점이 튄다 — `SeatSheet.tsx` 41~55줄, `PlaceDetailBody.tsx` 162줄 — `onClose`를 `useRef`로 들고 효과는 `[]`, 또는 `useCallback`.
- [주의] 예전 화면 전용 API와 코드가 남아 있다(`/api/regions` · `/api/situations` · `/api/score` · `/api/places/{id}` · 예약). 프론트 `types.ts`에도 쓰지 않는 필드(`Picks.day`, `PlaceDetail.address`, `PlaceDetail.conditions`, `Condition.hint`) — 정리 시점을 feature.md나 D-00X에 정하고, 쓰지 않는 필드는 지운다.
- [제안] `26 * 60`이 `NowBar`(`components.tsx` 148줄)에 직접 있다 — `format.ts AXIS_END`를 import, `axisPercent`의 `AXIS_START - 4 * 60`에 이름(`NIGHT_WRAP`)을 붙인다.
- [제안] `` `${t.slice(0, 2)}:${t.slice(2)}` ``가 `clockOf`가 있는데도 `ResultScreen.tsx` 35줄 · `api.ts search()`에 반복된다. `ResultScreen`의 fallback 좌표도 을지로 중심값 복사 — `clockOf` 사용, 좌표는 `DONGS`에 두거나 주석.
- [제안] `SeatSheet` 약 240줄, '지금 바로 / 30분 뒤' 문구가 세 곳 — 단계별 컴포넌트로 나누고 문구는 `WHEN` 하나. `components.tsx`(약 410줄)도 커지면 순수 UI와 스토어 묶인 것을 나눈다.
- [제안] `scripts/snapshot.py`의 `NearbyQuery(...)`가 `service.load_places`와 복사본 — `service.nearby_query(dong)` 하나를 둘 다 쓴다.
- [제안] `router.py ask_seat`가 서비스를 거치지 않고 문구 조립 · `LiveStatus` 반환을 맡는다 — `service.ask_seat(...)`로 옮겨 라우터를 얇게.
- [제안] 서버 깨움(`api.ts` 외부 스토어) · 전역 상태(Zustand) · 상세(`usePlace` 로컬)로 데이터 패턴이 셋 — 지금은 의도가 있어 그대로, 커지면 합치거나 이유를 주석으로.
