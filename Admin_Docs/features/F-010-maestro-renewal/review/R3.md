## 지적 (있을 때)
- [위험] real 모드에서 `YUMI_API_KEY`가 비어 있으면 저장본 대체가 동작하지 않는다 — `app/yumi/deps.py get_yumi_client` → `real.py RealYumiClient.__init__` — 생성자의 `YumiError(401)`이 `Depends` 단계에서 나와 `service.load_places`의 `try/except`에 닿지 않고 502가 된다. 키가 비면 mock(저장본)으로 내려가거나, 클라이언트 생성 실패도 `load_places`가 잡게 한다. real + 키 없음 → 200 / source=snapshot 테스트 추가.
- [주의] 유미 응답이 YumiError가 아닌 예외(JSONDecodeError · KeyError · TypeError)로 깨지면 저장본으로 가지 않고 500이 된다 — `real.py _get`, `service.py load_places` — `_get`에서 `YumiError(502)`로 감싸거나 `load_places`의 except를 넓힌다. `BrokenYumi` 테스트에 추가.
- [주의] 유미 장애(시간 초과)가 길면 요청마다 최대 약 40초를 기다린다 — `service.py load_places`, `real.py TIMEOUT_SECONDS=20 × 재시도 1회`, 프론트 `api.ts request`(타임아웃 없음) — 실패한 동네는 30~60초 동안 저장본으로 바로 가게 기억하고, 같은 동네 동시 요청은 한 번만 보내게 잠금을 둔다.
- [주의] 자리 물어보기 입력값을 서버가 검증하지 않는다 — `app/picks/schemas.py SeatAsk` — `people`에 범위가 없어 0 · -3 · 9999도 200. `Field(2, ge=1, le=10)`로 422, `test_bad_inputs_are_422`에 추가.
- [제안] 테스트 빈틈 — `tests/test_picks.py` — seat-ask 422, real 모드 시간 초과 · 파싱 실패 · 키 없음, `state=none` API 단 확인, `live-status` 모르는 queryId 404. 프론트 `useSeatAsk` 30초 처리 · `loadPicks` 늦은 응답 폐기는 테스트 러너가 없어 자동 검증 불가 — Vitest 도입을 다음 후보로.
- [제안] 프론트 에러 문구가 원인을 구분하지 않는다 — `ResultScreen.tsx` ErrorInline, `store.ts loadPicks` — 저장해 둔 `result.message`를 쓰지 않고 늘 "후보를 불러오지 못했어요". `current.message`를 넘기면 오프라인과 서버 오류가 구분된다.
