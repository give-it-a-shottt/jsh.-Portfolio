# T-002 "디자인시스템"이 0건 — 띄어쓰기·표기만 달라도 못 찾던 문제 (S1 정규화)

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과]
무엇이 문제였나: "디자인 시스템"은 찾는데 "디자인시스템"은 0건이었어요. 대문자가 전각(ＰｌａｎＦｏｒＭｅ)이거나 하이픈(react-query)이 붙어도 못 찾았어요.
어떻게 해결했나: 검색어와 데이터를 같은 모양으로 바꾼 뒤 비교해요. 띄어쓰기와 문장부호는 지우고, 대소문자·전각·자모 분리를 하나로 맞춰요. 시험지 0건 비율이 69%에서 51%로 줄었어요.

## 개발자 상세

### 증상
S0 기준으로 띄어쓰기 4개와 표기 차이 3개가 모두 0건이었어요.
- 띄어쓰기: "디자인시스템", "비밀번호찾기", "무료서버", "요청한도"
- 표기 차이: NFD "디자인 시스템"(자모가 풀린 글자), "ＰｌａｎＦｏｒＭｅ"(전각), "react-query"(데이터는 react query)

### 원인
`matchesQuery`·`matchesNote`가 `toLowerCase()` 한 번만 하고 `includes`로 글자 그대로 비교했어요. 대소문자만 맞추고 다른 차이는 그대로 남은 거예요.
- 데이터는 "디자인 시스템"(공백 있음), 검색어는 "디자인시스템"(공백 없음)이라 부분 문자열이 아니에요.
- NFD 한글은 눈에는 같아 보여도 코드값이 달라요. "디"가 글자 하나가 아니라 ㄷ+ㅣ 두 개로 들어와요.

### 가설과 실험
- 가설: 양쪽에서 공백을 지우고 비교하면 붙여 쓴 검색어도 걸린다. 띄어 쓴 검색어는 낱말마다 찾으니 원래처럼 걸린다.
- 걱정: 공백을 지우면 필드 경계나 낱말 경계를 넘어 엉뚱하게 걸릴 수 있어요.
- 확인: 검색어 42개의 결과 수를 S0와 비교했어요. 바뀐 건 S1이 겨냥한 7개(Q11~Q14, Q40~Q42)뿐이에요. 나머지 35개는 결과 수가 같고, 정답이 없어야 하는 검색어 3개도 0건 그대로예요.

### 해결
새 파일 [searchText.ts](../../Portfolio/frontend/src/portfolio/searchText.ts)에 규칙을 한 곳에 모았어요.
- `normalize`: NFC로 합치기 → 전각을 반각으로 → 소문자로 → 공백·문장부호·기호(`\p{P}\p{S}`) 지우기
- NFKC를 쓰지 않은 이유: NFKC는 전각도 바꿔 주지만, ㄱ·ㅏ 같은 낱자 모양까지 바꿔요. S5 초성 검색("ㄷㅈㅇ")에서 문제가 되니까 전각만 직접 바꿨어요.
- [data.ts](../../Portfolio/frontend/src/portfolio/data.ts)·[notes.ts](../../Portfolio/frontend/src/portfolio/notes.ts): 검색 글을 사례·노트마다 미리 한 번 정규화해 Map에 두고, 자동완성 필터에도 같은 규칙을 썼어요.
- 문장부호만 입력하면(예: "·") 남는 낱말이 없어서 0건이에요. 예전에는 "·"가 들어간 사례가 전부 나왔어요.

| 지표 | S0 | S1 | 증감 |
|---|---|---|---|
| 0건 비율 | 69% | 51% | -18%p |
| 상위 3 적중률 | 31% | 49% | +18%p |
| MRR | 0.29 | 0.47 | +0.18 |
| 찾은 비율 | 27% | 45% | +18%p |
| 엉뚱한 결과 | 0% | 0% | ±0 |

유형별로는 띄어쓰기와 표기 차이가 0%에서 100%가 됐어요. 기본·여러 단어는 100% 그대로예요(회귀 없음).

### 재발 방지
- 검색 비교는 `searchText.ts`의 함수만 써요. 화면 코드에서 `toLowerCase().includes`를 새로 쓰지 않아요.
- 채점기의 본문 검사도 같은 `normalize`를 불러 써요. 규칙이 두 군데로 갈라지지 않게요.

### 남은 것
- [주의] 자동완성 굵게 표시(`splitMatch`)는 아직 글자 그대로 찾아요. "디자인시스템"을 치면 "디자인 시스템"이 제안되지만 굵게 칠해지지 않아요. S5(하이라이트)에서 고쳐요.
- "노션으로 복습"(조사)은 여전히 0건이에요. "노션으로"를 통째로 찾기 때문이에요. S2(토큰화)에서 다뤄요.

### 배운 것
- 정규화는 "같은 것을 같게" 만드는 단계예요. 검색어와 데이터 양쪽에 똑같이 적용해야 효과가 나요.
- 규칙을 느슨하게 할 때는 맞힌 수만 보지 말고, 결과 수가 늘어난 다른 검색어가 있는지도 봐야 해요.
