# T-005 "마에스트르"·"vmffosvhal"·"타입스크립트"가 0건 — 오타와 같은 뜻의 다른 말 (S4)

## 한눈에 보기 (코드 몰라도 OK)
상태: [주의] 시험지 점수는 크게 올랐어요. 다만 처음 보는 검색어로 따로 재 보니 절반만 맞혔어요. 사전에 없는 말(도커, 레디스)은 여전히 못 찾아요.
무엇이 문제였나: 글자 하나만 틀려도("마에스트르"), 한글 자판을 영문으로 놓고 쳐도("vmffosvhal"), 같은 뜻을 다른 말로 써도("타입스크립트" ↔ TypeScript) 못 찾았어요.
어떻게 해결했나: 같은 뜻의 말 묶음(동의어 사전)으로 함께 찾아요. 아무것도 안 나오는 낱말은 자판을 바꿔 보고, 그래도 없으면 사이트에 있는 말 중 자모 한두 개만 다른 말로 고쳐요. 고쳤으면 결과 화면에 무엇으로 고쳤는지 알려요.

## 개발자 상세

### 증상 (S3 기준)
- 유사어 4개: "프론트"(3위, 찾은 비율 15%), "타입스크립트"·"레이트 리밋" 0건, "에러 처리"는 Back 사례를 못 찾음
- 한영 자판 3개, 자모 오타 3개: 모두 0건

### 원인
검색은 글자가 같아야 찾아요. 같은 뜻의 다른 표기, 자판 상태, 오타는 글자가 다르니 찾을 길이 없었어요.

### 해결
- **동의어 사전** [synonyms.ts](../../Portfolio/frontend/src/portfolio/synonyms.ts): 19개 묶음(프론트 = front = 프론트엔드, 에러 = 오류 = 예외 등). 검색어의 낱말이 사전에 있으면 같은 묶음의 말로도 찾아요. 띄어 쓴 두 낱말이 붙여서 사전의 말이면 하나로 합쳐요("레이트 리밋").
- **분야를 메타 칸에**: 사례의 분야(Front·Back·Design)와 노트의 분야를 메타 칸에 넣었어요. "프론트" → 동의어 "front" → Front 분야 전체가 걸려요.
- **한영 자판** [hangul.ts](../../Portfolio/frontend/src/portfolio/hangul.ts): 두벌식 자판표로 영문 → 자모 → 글자로 합쳐요(겹모음·겹받침, 받침이 다음 글자로 넘어가는 것까지). 반대 방향("ㅁㅊㅊㅑㅐ" → "accio")도 해요. 13개 변환 예시로 확인했어요.
- **자모 편집거리**: 글자를 자모로 풀어 한 쪽을 다른 쪽으로 바꾸는 데 몇 개를 고쳐야 하는지 세요(이웃 바꿈 1번 허용). "시스탬" → "시스템"은 ㅐ → ㅔ 하나라 1이에요.
  - 자모 4~9개면 1, 10개부터 2까지 고쳐요. 3개 이하나 영문 4글자 이하는 고치지 않아요("ai" → "ui"가 되지 않게).
  - 비교 대상은 사이트 글에 나오는 낱말(조사 뗀 모양)이에요. 거리가 같으면 더 많은 문서에 나오는 말을 골라요.
- **순서**: 원래 낱말과 동의어로 먼저 찾아요. 0건일 때만 자판 → 편집거리 순으로 고쳐요. 맞게 친 말을 바꾸지 않으려는 거예요.
- **안내**: 고쳐서 찾았으면 결과 요약 아래에 "'vmffosvhal' → '플랜포미'(으)로 고쳐서 찾았어요"를 보여 줘요(SearchResults).

| 지표 (시험지 39개) | S3 | S4 | 증감 |
|---|---|---|---|
| 0건 비율 | 23% | 3% | -21%p |
| 상위 3 적중률 | 74% | 95% | +21%p |
| MRR | 0.73 | 0.94 | +0.21 |
| 찾은 비율 | 71% | 95% | +24%p |
| 엉뚱한 결과 (없어야 하는 6개) | 0% | 0% | ±0 |

유사어·한영 오타·자모 오타 10개가 모두 상위 3 안에 들었어요. 나머지 유형은 S3와 같아요.

### 시험지에 맞춘 건 아닌지 확인 (처음 보는 검색어)
- ⚠️ 동의어 사전은 시험지 검색어("프론트", "타입스크립트", "에러", "레이트 리밋")를 본 상태에서 만들었어요. 그래서 점수가 부풀었을 수 있어요.
- 그래서 S4를 다 만든 뒤 처음 보는 검색어 10개(H01~H10)와 없어야 하는 검색어 3개(Q44~Q46)를 정하고, 한 번만 쟀어요. 이 결과를 보고 규칙을 고치지 않았어요. 채점기는 이 10개를 전체 점수에서 빼고 따로 보여 줘요(`heldOut`).

| 처음 보는 검색어 10개 | S3 코드 | S4 코드 |
|---|---|---|
| 상위 3 적중률 | 20% | 50% |
| 0건 비율 | 80% | 50% |

- 맞힌 것: 오타("algoritm", "디쟈인 시스템"), 자판("rjator" → 검색), 영문 섞인 말("photoshop 마스크", "mongodb 집계")
- 못 맞힌 것: "도커", "레디스", "깃허브 액션", "슈퍼베이스"(영문 도구 이름을 한글로 적은 말, 사전에 없음), "시간대 버그"(데이터에 "버그"가 없음)
- 새로 넣은 '없어야 함' 3개(유니티·스프링 부트·코틀린)는 모두 0건이에요. 오타 고치기가 엉뚱한 말로 바꾸지 않았어요.
- S3 코드는 커밋된 S3를 임시 작업 폴더(git worktree)에 꺼내 같은 시험지로 쟀어요.

### 비용
- 속도: 오타가 없는 검색은 그대로(약 0.02ms)예요. 모르는 낱말 3개짜리 검색이 가장 느려서 2.3ms예요. 첫 오타 고치기 때 자모 목록을 만드느라 한 번 12ms가 걸려요.
- 용량: 첫 화면 파일 압축 기준 202.2KB → 204.6KB(+2.4KB)

### 남은 것
- [주의] 사전 방식은 사전에 적은 말만 알아요. 영문 이름의 한글 표기(도커 ↔ Docker)는 규칙으로 바꾸기 어려워요. 이 사이트의 최종 방향인 AI 검색(Gemini)이나 임베딩이 풀 문제예요.
- 자동완성은 아직 오타·초성을 모르고, 일치 부분을 굵게 칠하는 기능도 아직 글자 그대로 비교해요(S5).

### 배운 것
- 시험지로 점수를 올리면 시험지에만 맞춘 규칙이 되기 쉬워요. 규칙을 만든 뒤에 정한 검색어로 따로 재야 진짜 실력이 보여요(머신러닝의 검증 세트와 같은 생각).
- 오타 고치기는 "아무것도 안 나올 때만" 해야 해요. 그래야 맞게 친 말을 엉뚱하게 바꾸지 않아요.
