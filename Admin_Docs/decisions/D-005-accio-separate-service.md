# D-005 Accio를 포트폴리오 밖 서비스로 분리하고 링크만 남기기

## 한눈에 보기 (코드 몰라도 OK)

상태: [주의] 분리 자체는 사용자 결정, 예전 주소 처리 방식은 확인 필요
무엇을 골랐나: 포트폴리오 안에서 돌던 Accio 앱(`#/accio`)을 지우고, 따로 배포한 Accio(accio-two.vercel.app)로 링크만 걸어요. 포트폴리오에는 Accio **프로젝트 페이지**(`#/project/accio`)와 디자인 사례, 팀 원본 정적 빌드(`/accio-v1/`)만 남아요.
왜: D-001에서 예고한 대로, Accio는 별도 서비스로 분리하고 포트폴리오에는 링크만 남기기로 했어요(사용자 확인, 2026-10-25 · 2026-11-05).

## 개발자 상세

- 상황: Accio를 FastAPI + Supabase + Gemini로 다시 만들어 Vercel에 따로 배포했어요. 포트폴리오 안 `src/projects/accio/`는 목 데이터로 흉내 내던 예전 화면이라, 두 곳에 같은 서비스가 다른 모습으로 있게 됐어요.

| 후보 | 장점 | 단점 |
| --- | --- | --- |
| A. 사이트 안 앱 삭제 + 링크 (선택) | 실제로 동작하는 한 곳만 보여 줌, 번들에서 Accio 청크 · 이미지 약 16MB 빠짐 | 예전 `#/accio/…` 주소를 처리해야 함 |
| B. 사이트 안 앱 유지 + 링크 추가 | 예전 주소가 그대로 열림 | 목업과 실제 서비스가 함께 보여 헷갈림 |

- 결정: A. `App.tsx`에서 Accio 라우트를 지우고, 예전 `#/accio`, `#/accio/…` 주소는 `#/project/accio`로 보내요(이 처리는 AI 판단 — 사용자 확인 필요). 배포 주소는 `data.ts`의 `ACCIO_LIVE` 한 곳에 둬요.
- D-001에 주는 영향: "앱 하나 + 해시 라우팅 + lazy"는 그대로예요. 다만 그 적용 범위가 Accio를 뺀 "포트폴리오 + 디자인 시안 + 마에스트로 · FLASEEK · techlearn · Nightly"로 줄었어요. 마에스트로도 나중에 같은 방식으로 분리할 예정이에요(D-001 사용자 확인).
- 그대로 둔 것: `Portfolio/backend/accio/` 뼈대와 GitHub Actions의 Supabase 깨우기 워크플로는 이번에 건드리지 않았어요. 실제 Accio의 DB 깨우기는 따로 배포한 쪽(Vercel Cron)이 해요.
- 바꿔야 하는 조건: 따로 배포한 Accio가 내려가거나 주소가 바뀌면 `ACCIO_LIVE`를 고치고, 서비스를 닫으면 프로젝트 페이지의 '서비스 열기' 버튼을 빼요.
