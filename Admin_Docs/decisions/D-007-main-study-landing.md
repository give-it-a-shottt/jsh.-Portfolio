# D-007 첫 화면을 프로젝트 중심 긴 페이지로, 헤더 탭은 Main / Study, 피그마는 공개 링크로

## 한눈에 보기 (코드 몰라도 OK)

상태: [통과] 방향 · 완료 기준 사용자 확인(2026-11-08)
무엇을 골랐나: 첫 화면 하나에 프로젝트 전부 · 스킬 · GitHub · 연락처를 모으고, 헤더 탭은 Design · Fullstack을 합쳐 Main / Study 두 개로 줄여요. 검색은 헤더에 작게 남기고, 디자인 원본은 피그마 공개 링크(보기 전용)로 보여 줘요.
왜: 사람들이 검색을 안 쓸 확률이 높고, 카드가 커서 새 프로젝트를 추가하기 부담스럽고, 한 서비스의 디자인 · 프론트 · 백엔드가 흩어져 있었어요(F-013 설계 의도, 사용자 확인).

## 개발자 상세

- 상황: F-011에서 홈은 소개 + 큰 검색창 + 대표 4개, 헤더 탭은 Design · Fullstack · Study였어요.

| 후보 | 장점 | 단점 |
| --- | --- | --- |
| A. 긴 첫 화면 + Main / Study (선택) | 스크롤만으로 다 보임, 프로젝트 추가는 데이터 한 줄 | 검색 결과 화면의 분야 탭과 헤더 탭이 서로 다름(Q-006) |
| B. F-011 그대로 + 대표 카드만 늘림 | 바뀌는 코드가 적음 | 검색 비중이 그대로, 카드가 커서 늘리기 부담 |

- 결정: A. 홈 카드 = `PROJECT_LIST` 전부(대표를 따로 고르지 않음). 검색은 헤더 `SearchBox` `sm`.
- 피그마: 예전에는 "피그마 주소는 공개 사이트에 넣지 않는다"(`data.ts` 주석)였어요. 사용자가 파일마다 공유를 "Anyone · View, 복사 · 내보내기 끔"으로 바꾸고 링크를 주기로 정해서 바꿨어요. 공유 추적 값(`t=`)은 빼고 넣고, `npm run check`가 확인해요.
- 바꿔야 하는 조건: 프로젝트가 많아져 첫 화면이 너무 길어지면 카드에 필터 칩(전체 / Design / Front / Back)을 더해요. 피그마 파일을 비공개로 돌리면 그 프로젝트의 `figma`를 빼야 해요(지금은 필수 칸).
