# D-009 홈 첫 화면은 랜딩 없이, 메인 5개를 스크롤 섹션으로

## 한눈에 보기 (코드 몰라도 OK)

상태: [통과] 사용자 결정(2026-11-25)
무엇을 골랐나: 첫 방문 때 홈을 가리던 자소서형 랜딩을 없애고, 홈에서 메인 프로젝트 5개를 스크롤 한 화면씩 소개해요. 왼쪽 글은 제자리에서 바뀌고 오른쪽 화면은 위로 밀려 올라가요. 색은 흰 바탕에 빨강을 포인트로만 써요.
왜: 기존의 복잡함을 해소한다(F-018 설계 의도, 사용자 확인).

## 개발자 상세

- 상황: 첫 방문이면 랜딩([F-014](../features/F-014-cover-letter-landing/feature.md))을 지나야 홈이 보였고, 홈은 메인 5개가 같은 크기 카드로 나란히 있었어요([D-008](D-008-main-sub-projects.md)).

| 스크롤 방식 | 장점 | 단점 |
| --- | --- | --- |
| A. 글 고정 + 화면 교체 (선택) | 자리가 멈춰 있어 글과 화면을 함께 본다 | 고정 구간 계산, 좁은 화면 대체가 필요 |
| B. 한 화면씩 흐르기 | 가장 가볍다 | 프로젝트마다 무게가 비슷해 보인다 |
| C. 카드가 겹쳐 쌓이기 | 인상이 강하다 | 내용이 길면 잘린다 |
| D. 멈추는 스냅 | 장면이 분명하다 | 트랙패드 · 모바일에서 답답하다 |

- 결정: A, 스냅 없음(사용자 선택, 2026-11-25). 랜딩 글은 한 문장만 홈 첫 문장으로 쓰고 나머지는 지워요(사용자 선택). 빨강은 포인트만(사용자 선택).
- 좁은 화면(1024 미만) · 낮은 창(700 미만) · 움직임 줄이기 설정이면 고정하지 않고 펼쳐요(AI 기재, 피그마 'Motion 규칙' 7).
- 데이터: `projects.ts`의 메인 프로젝트에 `showcase`(한 줄 · 숫자 이름 두 개 · 화면)를 두어요. 숫자 값은 `numbers`에서 찾아 두 곳이 어긋나지 않게 하고, 메인인데 `showcase`가 없으면 `npm run check`가 잡아요(AI 기재).
- 바뀌는 것: D-007의 '소개 → 프로젝트 → 스킬' 긴 페이지와 헤더 Main / Study는 그대로예요. D-008의 '메인은 큰 카드'가 '메인은 스크롤 섹션'으로 바뀌고, `mainGridLayout`은 지웠어요. 메인 · 서브 구분과 순서는 D-008 그대로예요.
- 바꿔야 하는 조건: 메인이 6개를 넘으면 스크롤 길이(프로젝트당 한 화면)를 다시 정해요.
