## 개발자 상세

- 상황: [D-007](D-007-main-study-landing.md)에서 "홈 카드 = `PROJECT_LIST` 전부(대표를 따로 고르지 않음)"로 정했고, F-013에서 `FEATURED_SLUGS`를 지웠어요. 이 결정은 그중 '대표를 따로 고르지 않음'을 바꿔요. 긴 첫 화면 · Main / Study · 피그마 공개 링크는 그대로예요.

| 후보 | 장점 | 단점 |
| --- | --- | --- |
| A. 메인은 큰 카드 3칸, 서브는 지금 카드 (선택) | 대표 3개가 한눈에, 서브는 그대로 촘촘히 | 카드 컴포넌트가 하나 더 생김 |
| B. 카드는 그대로, 제목만 둘로 | 바뀌는 코드가 가장 적음 | 대표와 나머지의 무게 차이가 잘 안 보임 |

- 결정: A (사용자 선택, 2026-11-19). 순서는 디딤 · Accio · 마에스트로(사용자 선택).
- 데이터: `PROJECT_LIST` 하나에 `tier: 'main' | 'sub'`를 두고 메인을 앞에 모아요. 목록을 둘로 나누지 않아서 '다음 프로젝트'가 그대로 한 바퀴로 돌고, `npm run check`가 메인 3개 · 앞쪽 · 첫 번째 디딤을 확인해요. (AI 기재)
- 바꿔야 하는 조건: 대표 프로젝트가 늘거나 줄면 `tier`를 바꾸고, `checks/run.mjs`의 메인 순서 기댓값(사용자가 정한 순서라 고정)도 같이 바꿔요. 메인이 4개를 넘으면 큰 카드 줄을 다시 정해요.

- 덧붙임(2026-11-22, F-016): 아래 '바꿔야 하는 조건'에 따라 메인을 4개로 늘렸어요. 순서는 Agora AI 토론장 · 디딤 · Accio · 마에스트로(사용자 선택 — "디딤 앞에, 메인이 4개가 되도록"). 4개를 한 줄 3칸에 두면 하나가 혼자 남아서 4개일 때만 2×2로 놓아요(AI 임시 선택, 디자인은 사용자 평가). 칸 수는 `projects.ts`의 `mainGridLayout`이 정하고 `npm run check`가 확인해요.
- 덧붙임(2026-11-23, F-017): 메인을 5개로 늘렸어요. 순서는 거기붐벼? · Agora AI 토론장 · 디딤 · Accio · 마에스트로(사용자 선택 — 마에스트로를 서브로 내려 2×2를 유지하는 안, 서브에 넣는 안과 견주어 "메인 맨 앞에 넣어 5개, 위 3 · 아래 2"). 5개는 `mainGridLayout`의 기존 규칙대로 한 줄 3칸이에요. 위 '메인이 4개를 넘으면 큰 카드 줄을 다시 정해요'에 대한 답이 이 선택이에요. `npm run check`가 메인 5개 · 3칸 · 첫 번째 geogi를 확인해요.

- 덧붙임(2026-11-25, F-018): 메인의 '큰 카드'는 [D-009](D-009-home-showcase.md)에서 스크롤 섹션으로 바뀌었어요. 메인 · 서브 구분, 메인 5개와 순서는 그대로예요. `mainGridLayout`은 지웠어요.
