# D-004 노션 공부 노트는 터미널 한마디로 반자동 옮기기

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과] 사용자가 직접 골랐어요(2026-10-26).
무엇을: 노션에 새 공부 페이지를 올리고 터미널에 "노션 새 노트 옮겨줘"라고 하면, Claude가 아직 사이트에 없는 페이지만 찾아요. 그다음 "무엇을 배웠는지"로 정리한 초안을 보여 주고, 확인을 받은 뒤에 사이트에 올려요. 편집자가 원고를 받아 다듬은 뒤 실어 주는 것과 같아요.
왜: 노션 페이지는 문답 기록이라 그대로 실을 수 없고, 면접관에게 보일 글은 내가 확인하고 올리고 싶어서요.

## 개발자 상세

### 상황
- 사용자는 노션의 두 페이지(학습 · 포토샵/일러스트) 아래에만 공부 문답을 올린다.
- 사이트 노트([notes.ts](../../Portfolio/frontend/src/portfolio/notes.ts), [noteData/](../../Portfolio/frontend/src/portfolio/noteData/))는 원문 복사가 아니라 요약·포인트·막힌 것·써먹은 곳을 다듬은 글이다.
- 새 페이지를 손으로 찾아 옮기는 게 번거롭다.

### 후보
| 후보 | 방법 | 장점 | 단점 |
|---|---|---|---|
| A. 터미널 반자동 (선택) | 스킬 `notion-notes-sync`가 Notion MCP로 새 페이지를 찾아 초안을 만들고, 사용자가 확인하면 커밋 | 비밀키·비용 없음. 공개 전에 내가 검토. 문답 → 배운 것 정리 품질 유지 | 내가 한마디는 해야 함 |
| B. 완전 자동 | GitHub Actions가 매일 노션 API로 찾고 AI로 요약해 자동 배포 | 손댈 일 없음. 백엔드 공부거리 | 노션 토큰·AI API 키(유료) 필요. 검토 안 된 글이 바로 공개 |
| C. 감지만 자동 | 새 페이지를 매일 찾아 GitHub 이슈로 알림, 옮기기는 A | 놓치지 않음 | 노션 토큰 필요. 지금 규모엔 과함 |

### 결정
- A를 골랐다.
- 무엇을 옮겼는지는 장부 [notion-ledger.json](../../Portfolio/frontend/src/portfolio/noteData/notion-ledger.json)에 page id로 남긴다. 그래서 같은 페이지를 두 번 옮기지 않는다.
- 같은 결정에서 알고리즘(코테 풀이)도 Back 노트로 싣기로 했다.

### 결과로 생기는 제약
- 노션에서 페이지를 지우거나 옮겨도 사이트 노트는 그대로 남는다. 필요하면 손으로 지운다.
- 노션 페이지 내용을 나중에 고쳐도 자동으로 다시 반영되지 않는다(장부에 이미 있으므로). 고치고 싶으면 그 노트만 다시 정리하라고 말한다.

### 이 결정을 바꿔야 하는 조건
- 새 페이지가 하루 여러 개로 늘어서 한마디도 번거로워지면 C(감지 자동화)를 붙인다.
- 백엔드 로드맵의 노션 동기화 단계(S6)를 할 때 B를 공부 삼아 다시 검토한다.
