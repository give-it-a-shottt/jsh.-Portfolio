# T-004 "프론트"의 정답이 6위로 밀리고 문장형 검색은 0건 — 레벨 순 정렬과 AND 규칙 (S3 랭킹)

## 한눈에 보기 (코드 몰라도 OK)
상태: [주의] 순서와 문장형 검색은 나아졌어요. 남은 건 동의어·오타(S4)이고, "서버가 잠들어서 느린 문제"처럼 데이터에 없는 표현은 키워드 검색으로는 못 찾아요.
무엇이 문제였나: 결과 순서가 "얼마나 관련 있나"가 아니라 사례 레벨 순이었어요. 그래서 본문에 한 번 스친 사례가 위로 올라왔어요. 또 낱말이 하나라도 없으면 0건이라 "외부 API 느릴 때 어떻게 했나" 같은 질문은 못 찾았어요.
어떻게 해결했나: 낱말이 제목에 있는지, 얼마나 드문 낱말인지로 점수(BM25)를 매겨 순서를 정해요. 질문에 붙는 군더더기 말은 빼고, 낱말이 셋 이상이면 대부분만 맞아도 결과에 넣어요. 상위 3 적중률이 67%에서 74%가 됐어요.

## 개발자 상세

### 증상 (S2 기준)
- "프론트": 본문에 "프론트"가 한 번 나오는 Back 사례(레벨 3)가 Front 관련 결과보다 위에 와서, 첫 정답이 6위였어요.
- "외부 API 느릴 때 어떻게 했나", "AI 쇼핑몰 만든 거": "어떻게", "했나", "거"는 데이터에 없거나 아무 글에나 있어요. AND 규칙에서는 0건이거나 엉뚱한 1건이 나왔어요.

### 원인
- `search()`가 고른 문서를 `rankCases`(레벨 → 날짜)로만 줄 세웠어요. 검색어와 얼마나 관련 있는지는 순서에 들어가지 않았어요.
- 모든 낱말이 있어야 하는 AND 규칙이라, 문장으로 물으면 군더더기 말 하나 때문에 결과가 사라졌어요.

### 해결 ([search.ts](../../Portfolio/frontend/src/portfolio/search.ts), [searchText.ts](../../Portfolio/frontend/src/portfolio/searchText.ts))
- **BM25 점수**: 낱말마다 (드문 정도 IDF) × (나온 횟수, 많이 나와도 끝없이 오르지 않게 누름)를 더해요. 긴 글은 덜 쳐요. 상수는 널리 쓰는 기본값(K1 1.2, B 0.75)이에요.
- **필드 가중치(BM25F)**: 문서를 제목·메타(태그·keywords)·요약·본문 네 칸으로 나눴어요. 무게는 3 : 2 : 1.5 : 1이에요. 칸을 나눈 김에 칸 경계를 넘는 일치는 없앴어요.
- **레벨은 덤으로**: 점수에 ×(1 + 0.1 × (레벨 − 1))을 곱해요. 레벨 4는 ×1.3이에요. 점수가 같으면 예전처럼 레벨 → 날짜 순이에요.
- **군더더기 말 빼기**: "어떻게", "했나", "거", "때", "만든" 등 31개는 검색어에서 빼요. 전부 군더더기면 빼지 않아요.
- **minimum_should_match**: 낱말이 두 개까지는 전부 맞아야 하고, 세 개부터는 75%(내림)만 맞으면 돼요. Elasticsearch와 같은 방식이에요. 두 개를 전부 요구하는 이유는 "안드로이드 앱"이 "앱" 하나로 아무 앱 사례에나 걸리지 않게 하려는 거예요.
- **짧은 영어 낱말**: 3글자 이하 영어·숫자 낱말은 영어 단어와 통째로 같을 때만 찾아요. 측정해 보니 "AI"가 "detail" 같은 단어 속에도 걸려 결과가 20건이었는데, 고친 뒤에는 실제로 AI를 다룬 4건만 나와요.
- '전체' 탭 배치 값(`NOTES_AFTER`, `NOTES_IN_MODULE`)을 search.ts로 옮겼어요. SearchResults와 채점기가 같은 값을 써요.

| 지표 | S2 | S3 | 증감 |
|---|---|---|---|
| 0건 비율 | 28% | 23% | -5%p |
| 상위 3 적중률 | 67% | 74% | +8%p |
| MRR | 0.67 | 0.73 | +0.06 |
| 찾은 비율 | 66% | 71% | +5%p |
| 엉뚱한 결과 | 0% | 0% | ±0 |

- "프론트": 첫 정답 6위 → 3위. "외부 API 느릴 때 어떻게 했나", "AI 쇼핑몰 만든 거": 0건·오답 → 1위 정답
- 자연어 유형 상위 3 적중률 0% → 50%. 나머지 유형은 S2와 같아요(회귀 없음).
- 용량: 첫 화면 파일 압축 기준 +0.8KB. 속도: 검색 한 번 평균 0.027ms

### 바뀐 동작
- [주의] 낱말이 세 개 이상이면 결과가 늘 수 있어요. "React 상태 관리"는 2건에서 5건이 됐어요(1위는 그대로). 일부 낱말만 맞은 문서는 점수가 낮아 아래쪽에 와요.
- 결과 순서가 레벨 순이 아니라 점수 순이에요. 검색어 없이 볼 때(전체 목록)는 그대로 레벨 순이에요.

### 남은 것
- "서버가 잠들어서 느린 문제", "날짜가 하루 밀리는 버그": 데이터는 "잠들고", "어제가 됨"처럼 다른 말로 적혀 있어요. 낱말을 맞추는 검색으로는 한계가 있어요. 이 사이트의 최종 방향인 AI 검색(Gemini)이 풀 문제예요.
- 유사어("타입스크립트", "레이트 리밋")와 오타는 S4에서 다뤄요.
- ⚠️ 채점기는 정답이 결과에 있는지는 재지만, 결과에 섞인 잡음(정밀도)은 '없어야 하는 검색어' 3개로만 봐요. "AI" 같은 잡음은 이번처럼 따로 재야 했어요.

### 배운 것
- 찾는 것(재현율)과 줄 세우는 것(랭킹)은 다른 문제예요. S2에서 넓힌 만큼 S3에서 순서를 잡아야 했어요.
- 공백을 지우고 비교하는 S1의 선택은 한글에는 잘 맞지만, 짧은 영어에서는 단어 속 글자에 걸리는 부작용이 있었어요.
