# T-001 검색 베이스라인 — 검색어 3개 중 2개가 0건

## 한눈에 보기 (코드 몰라도 OK)
상태: [주의] 측정만 끝났어요. 고치는 건 S1부터 해요.
무엇이 문제였나: 시험지 검색어 36개로 채점해 보니 24개(67%)가 결과 0건이었어요. 맞힌 건 띄어쓰기·철자가 데이터와 똑같은 검색어뿐이었어요.
어떻게 해결하나: 원인이 유형마다 달라서 단계별로 고쳐요. 띄어쓰기는 S1, 조사·본문은 S2, 긴 문장은 S3, 오타·유사어는 S4에서 고쳐요. 숫자는 매번 같은 시험지로 다시 재요.

## 개발자 상세

### 증상
`npm run search:eval` 첫 실행 결과([runs/S0.json](../../Portfolio/frontend/search-eval/runs/S0.json))예요.

| 지표 | S0 (검색어 36개) | S0 재측정 (39개) |
|---|---|---|
| 0건 비율 | 67% (24/36) | 69% (27/39) |
| 상위 3 적중률 | 33% | 31% |
| MRR | 0.31 | 0.29 |
| 찾은 비율 | 29% | 27% |
| 엉뚱한 결과(정답 없어야 하는 3개) | 0% | 0% |

💡 S1을 시작하며 표기 차이 검색어 3개(Q40~Q42)를 더하고, 고치기 전 코드로 다시 쟀어요. runs/S0.json은 39개 기준이에요.

유형별로 보면 맞힌 건 기본(7개)과 여러 단어(3개)뿐이에요. 유사어는 50%, 나머지 유형은 모두 0%예요.

### 원인
검색 규칙이 하나뿐이에요. [data.ts](../../Portfolio/frontend/src/portfolio/data.ts)의 `matchesQuery`와 [notes.ts](../../Portfolio/frontend/src/portfolio/notes.ts)의 `matchesNote`가 같은 규칙을 써요. 공백으로 나눈 단어가 **모두** 제목·설명·태그·keywords 안에 **글자 그대로** 있어야 결과로 나와요. 그래서 실패 유형마다 원인이 하나씩 보여요.
- 띄어쓰기("디자인시스템"): 데이터에는 "디자인 시스템"으로 띄어 써 있어서, 붙여 쓴 글자가 통째로 없어요.
- 조사("노션으로 복습"): "노션으로"라는 글자가 데이터에 없어요. 단어 하나라도 없으면 AND 규칙에서 전체가 0건이 돼요.
- 본문("웨이팅", "히스토그램"): 사례 상세(문제·해결)와 노트의 "배운 것"은 검색 대상이 아니에요. 채점기가 본문에는 이 단어들이 있다는 걸 확인했어요(5개 모두).
- 자연어("외부 API 느릴 때 어떻게 했나"): "어떻게", "했나"는 데이터에 없어서, AND 규칙이 결과를 전부 지워요.
- 오타·유사어("마에스트르", "vmffosvhal", "타입스크립트"): 글자가 하나라도 다르면 못 찾아요.

### 가설과 실험
- 가설: 0건은 대부분 "AND + 글자 그대로 일치" 규칙 때문이고, 데이터가 부족해서가 아니다.
- 실험: 채점기가 놓친 정답마다, 검색어 낱말이 본문까지 합친 글에 다 들어 있는지 확인했어요. 본문 유형 5개는 정답 6건이 모두 본문에 있었어요. 데이터는 있는데 검색이 안 보는 거예요.
- "프론트"는 0건이 아니라 6건이 나왔어요. 정답(Front 사례 7개 + Front 노트 19개, 사용자 검토로 노트도 정답에 넣음) 중 찾은 건 노트 3개(12%)뿐이에요. Front 사례는 하나도 없었어요. 데이터에 "프론트"라는 글자가 거의 없어서예요(S4 동의어에서 다뤄요).

### 해결 (계획)
| 단계 | 고칠 유형 | 검색어 수 |
|---|---|---|
| S1 정규화 | 띄어쓰기 | 4 |
| S2 토큰화·역색인 | 조사, 본문 | 8 |
| S3 랭킹(BM25) | 자연어 | 4 |
| S4 오타·유사어 | 유사어, 한영 오타, 자모 오타 | 10 |

### 재발 방지
- 검색 코드를 고치면 `npm run search:eval`로 S0와 비교해요. 기본·여러 단어 유형이 100% 아래로 떨어지면 개선이 아니라 회귀예요.
- 정답이 없어야 하는 검색어 3개도 같이 봐요. 규칙을 느슨하게 하면 엉뚱한 결과가 늘 수 있어요(S3에서 AND를 OR+순위로 바꿀 때 특히).

### 배운 것
- 고치기 전에 재는 도구부터 만들어야, "좋아졌다"를 숫자로 말할 수 있어요.
- 같은 0건이라도 원인이 다섯 가지였어요. 유형별로 나눠 재지 않았으면 하나로 뭉뚱그렸을 거예요.
