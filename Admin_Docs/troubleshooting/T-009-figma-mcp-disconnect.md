# T-009 피그마 MCP가 큰 요청에서 끊김 — 한 장씩, 끊기면 한 번 더

## 한눈에 보기 (코드 몰라도 OK)
상태: [주의] 피하는 방법은 찾았지만, 끊기는 원인은 피그마 쪽이라 완전히 막지는 못해요.
무엇이 문제였나: 마에스트로 리뉴얼 화면을 피그마에서 받아 오는데, 큰 화면이나 여러 장을 한꺼번에 요청하면 연결이 끊겼어요. 같은 화면이 5번 연속 실패하기도 했어요.
어떻게 해결했나: 한 번에 한 장씩, 기본 크기로 받고, 끊기면 같은 요청을 한 번 더 보냈어요. 남은 6장을 이렇게 다 받았고, 끊긴 2번도 다시 보내니 바로 됐어요.

## 개발자 상세

### 증상 (2026-11-01, F-010)
```
Anthropic proxy: MCP server connection lost
```
- `get_design_context`로 화면 전체(코드 + 스타일)를 받으면 응답이 커서 자주 끊겼어요. 다시 연결해도 같았어요.
- `get_screenshot`도 큰 크기(1440 · 2048)를 지정하거나 여러 개를 동시에(병렬) 부르면 더 자주 끊겼어요.
- 명세표(57:224)는 크기를 줄여도 계속 실패했어요(앞 세션).

### 원인 (추정)
- 응답이 크면 프록시 연결이 끊기는 것으로 보여요. 다만 기본 크기(1024)로 보낸 요청도 한 번 끊겼고, 나중에는 1440 · 1808 크기도 한 번에 됐어요. 그래서 크기만이 원인은 아니고, 그때그때 연결 상태도 영향을 주는 것 같아요.

### 해결
- 화면 코드가 필요하면 화면을 작은 노드로 나눠 `get_design_context`를 불러요.
- 이미지는 `get_screenshot`으로 주소만 받고 `curl`로 내려받아요(주소는 금방 만료돼서 받자마자 저장해요).
- **한 번에 하나씩** 부르고, 끊기면 **같은 요청을 한 번 더** 보내요. 이번에는 6장 중 2장이 한 번씩 끊겼다가 두 번째에 됐어요.
- 크기는 기본(1024)으로 먼저 받고, 글씨가 작으면 원래 크기로 한 번만 더 시도해요(명세표 1808 · 상세 PC 1440 모두 됨).

### 재발 방지
- 피그마 작업은 병렬로 부르지 않아요.
- 받은 원본은 저장소 밖 임시 폴더(`design_import/`, 커밋 안 함)에 두고, 사이트에는 webp로 바꿔 넣어요.
- 피그마 파일 주소 · 키는 공개 문서에 적지 않아요.
